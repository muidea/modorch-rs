# 开发草案与后续版本迁移

0.1.0 是首发前内部开发标号，本次首发统一为 0.0.1；这不是已发布 0.1.0 的降级。没有旧正式发布版本的二进制兼容承诺。按实际源码与 Bundle 指纹匹配，不能把文档规范 1.x 当作 crate 版本。

| 旧草案/旧字段 | 当前使用方式 |
|---|---|
| Vec<HandlerRegistration> | Module::handlers / Initiator::event_endpoint 返回 Option，多个订阅置于单套注册 |
| TaskSpec / once / every / 自填 Owner | Context.tasks 的闭包 spawn / TaskFactory delay / interval |
| MessageId / source 必填 | OperationId / 外部 source=None，由框架填因果身份 |
| PartialDelivery / ResourceUnavailable | PublishReport.deliveries / ServiceUnavailable |
| StartupError.source: FrameworkError | Box<FrameworkError>；按值匹配先解引用，Error::source 仍可 downcast |
| 新增配置结构体字段 | 使用 ..Default::default() 并核对 payload_bytes、ExecutionResources、指标快照 |
| 无预算重启或消息重放 | Restart 为累计预算与代际屏障，不自动重放有副作用消息 |

逐步升级：固定当前源码 → 保存应用测试 → 对照 Facade Rustdoc 改调用 → 更新匹配 Skill → fmt/check/clippy/test/doc → 注入启动/超时/关闭失败 → 保留证据。详细 Feature / MSRV 表在[兼容性说明](../compatibility.md)。

## MQTT Topic 迁移（2026-11-04）

本次从 0.0.1 迁移至 0.0.2，是破坏性语义收口；旧 tag 保留旧实现，使用当前源码需更新匹配的 Skill 1.0.5 / Contract 1.1.0。

1. 搜索订阅中的 `:id` / `:parameter`，单层通配改为 `+`，例如 `orders/:id/changed` → `orders/+/changed`；Handler 从实际 Topic 读取 ID。字面 `:id` 保留，无参数提取 API。
2. 修复中间 `#`、嵌入 `a+` / `a/b#`，改合法 Filter 加业务过滤或调整 Topic 树。无 Legacy 兼容开关。
3. 检查 `orders/+` 新接受的 `orders/`、`orders/#` 的 `orders` 及前后 `/`/重复 `/`；审计 Handler 空层假设、授权/ACL 的扩大匹配集合。根 `#` / `+` 不再覆盖 `$SYS`，显式订阅 `$SYS/#`。
4. Name 使用实际路径，禁止把 Filter 当作 publish/command/request Topic；空串、NUL、`+/#`、超 65535 UTF-8 字节均 InvalidConfig。配置本地 max_topic_bytes 时区分协议上限；合法但超预算返回 ResourceLimit。大小写、空格、Unicode 不自动规范化。
5. 更新 matcher 断言和业务回归；运行 topic_conformance、完整 workspace、文档/Skill 门禁，再安装新指纹 Bundle。`$share/...` 只按基础路径匹配，不承诺共享组、Broker、QoS 或 Session。

[本轮验证](../validation/2026-11-04/mqtt-topic-alignment/README.md)保留执行证据，未执行的独立 Agent 仍 NotRun。

0.0.2 的框架/模板清单、锁文件与 Skill 指纹重新生成，实际发布验证见 [0.0.2 验收](../validation/2026-11-04/release-0.0.2/README.md)。

## 2026-11-06 Module 入口增强（0.0.2 开发树）

新增默认无操作的 `Module::activate_ingress`，覆盖时在 impl 添加 `#[async_trait]`，不覆盖的既有 Module 无需修改。同名固有方法在调用时可能遮蔽 trait 方法，可用 `<T as Module>::activate_ingress` 限定。只通过 Facade 引入 API，不放开 Module 的服务发布权限。

将 start/ready 中的监听迁入 activate_ingress；setup 若预绑定，改用未 listen 的 TcpSocket，避免 TcpListener::bind 提前接受 TCP 握手。长期任务使用 ctx.tasks，入口消息使用 ctx.event_hub.external()，停止时保留任务/资源至实际退出。

监督重建的激活失败现在会先补偿并在剩余累计预算内重试，预算耗尽才 FailFast；旧任务/服务能力失效，应用级 Hub 仍有效。需要依赖“激活失败立即全应用退出”的宿主应检查 FailurePolicy。框架版本仍为 0.0.2 开发树，已发布 v0.0.2 工件不含此变更；使用 Skill 1.0.6 / Contract 1.2.0 及新源码指纹。验证见[入口验收](../validation/2026-11-06/module-ingress/README.md)。

## 升级至 0.0.3 Candidate

从 v0.0.2 升级时使用 v0.0.3 tag、Contract 1.2.0 与 Skill 1.0.7 的新指纹 Bundle；旧 Module 可保留默认无操作入口 Hook。需要网络入口的 Module 按上节覆盖 activate_ingress，将 listen 从 setup/start/ready 移入该 Hook，并测试部分激活失败、重建绑定失败和检查式关闭。监督重建激活失败改为补偿后在累计预算内重试；应用级 Hub 句柄继续有效。详见 [发布说明](../releases/0.0.3.md)及[发布验收](../validation/2026-11-06/release-0.0.3/README.md)。
